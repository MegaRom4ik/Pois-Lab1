# ППОИС — лабораторные работы на C++

В `lab1` реализованы два варианта: **Вектор** и **Крестики-нолики**.
Используется C++17. Интерфейсы классов находятся в `.hpp`, реализация в `.cpp`,
консольные программы — в отдельных `main.cpp`. Тесты используют doctest 2.4.11.

## Сборка и запуск

Нужны Clang, Make и curl. Для отчёта покрытия — LLVM; для документации — Doxygen.
В Ubuntu: `sudo apt-get install clang llvm make curl python3 doxygen cppcheck`.
В macOS нужны согласованные версии Xcode/Command Line Tools; Doxygen можно установить через Homebrew.

```sh
make all
./build/vector_cli
./build/tictactoe_cli
make test
make coverage
make docs
```

В macOS, если LLVM не находится в PATH:

```sh
make coverage LLVM_COV="$(xcrun --find llvm-cov)" LLVM_PROFDATA="$(xcrun --find llvm-profdata)"
```

При первом запуске тестов Make скачивает заголовок doctest из официального
репозитория в игнорируемую папку `build`. Документация: `build/docs/html/index.html`.
Отчёт покрытия: `build/coverage/index.html`. Проверяется строго **более 90% строк
каждого предметного класса**; меню и сторонняя библиотека не входят в этот показатель.

## Правила вектора

Ввод: `x1 y1 z1 x2 y2 z2`. Направление — конец минус начало.
Сложение, вычитание, векторное произведение и масштабирование сохраняют начало
левого операнда. Равенство означает совпадение координат направления, даже если
начала разные; сравнение порядка выполняется по длине. Равенство `double` точное;
в тестах приближённых результатов используется `doctest::Approx`.
Операции с очень большими/малыми числами подчиняются ограничениям `double`.
Нулевой делитель и косинус с нулевым вектором вызывают исключения.
Нечисловые или бесконечные координаты не принимаются.

## Правила крестиков-ноликов

Квадратное поле имеет размер от 1 до 1000; предел защищает от чрезмерного
выделения памяти. Выигрывает игрок, заполнивший **всю** строку, столбец или одну
из двух диагоналей. Первым ходит X. После победы или ничьей новые ходы запрещены.
В меню координаты начинаются с 1; в классе — с 0.
`game[row * size + column]` позволяет читать клетку и записывать ход через
проверяющий прокси, не открывая прямой доступ к массиву.

Сохранение содержит размер, число ходов и историю индексов клеток. Загрузка
повторяет историю и проверяет каждый ход; повреждённый файл не меняет текущую игру.
Копирование класса независимо копирует поле и историю благодаря `std::vector`.

## GitHub

Все лабораторные хранятся в одном репозитории. Оба варианта первой работы
находятся в `lab1/vector` и `lab1/tictactoe`. Папки `lab2`–`lab4` следует добавить
при реализации соответствующих работ.
Рабочая ветка: `feature/lab1-vector-tictactoe`. Изменения в `main` входят через
Pull Request после одобрения преподавателя.

GitHub Actions на push и Pull Request собирает программы, запускает тесты,
проверяет покрытие, выполняет cppcheck и генерирует Doxygen-документацию.
Отчёты и программы доступны в артефакте запуска Actions.
При отправке тега вида `v1.0.0` после успешных проверок автоматически создаётся
Release с архивом статических программ для Linux x86_64 и документацией.
На Windows потребуется WSL или отдельная сборка, на macOS — локальная сборка.
Тег выпуска создавайте после одобрения и слияния Pull Request.

## Что понимать на защите

- Разность концов даёт координаты вектора; длина вычисляется через `std::hypot`.
- Векторное произведение: `(ay*bz-az*by, az*bx-ax*bz, ax*by-ay*bx)`.
- Косинус — скалярное произведение нормированных направлений.
- Составные операторы вычисляют результат до присваивания: ошибка сохраняет объект.
- После хода проверяются только проходящие через клетку линии: время O(N).
- Поле хранится в плоском массиве: индекс `row*N+column`, память O(N²).
- Прокси `Cell` позволяет проверять присваивание через `operator[]`.
- Загрузка выполняется во временный объект, поэтому частичный ввод не портит игру.
- Ресурсами управляют стандартные контейнеры; ручные `new`/`delete` не нужны.
